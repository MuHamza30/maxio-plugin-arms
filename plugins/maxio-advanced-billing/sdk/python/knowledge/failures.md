# Maxio rejections: status and message, cause, what to do

To get the status and Maxio's own message out of an SDK error, see `docs/error-handling.md`, section "Maxio: reading a rejection".

Every rejection Maxio is known to return for the operations that have notes, 147 rows in all.
Find the status, then search this page for a distinctive part of the message. Read the row before you
change code: a 422 is often not a defect in your request. The same rows sit in each operation's notes
under **When it fails**; the Operation column links there.

## 400

| Message | Operation | Cause | Do |
|---|---|---|---|
| (any) | [`override_subscription`](operations/subscriptions.md#overridesubscription) | A field this call does not accept was sent [spec] | Send only the fields the contract lists for this call |
| (any) | [`purge_subscription`](operations/subscriptions.md#purgesubscription) | Wrong `ack`, or the site is not in test mode *(inferred; the spec gives the status with no message)* | Check the customer id and that `read_site` returns `test: true` |
| "Purchase Declined. The subscription is now in the …" | [`activate_subscription`](operations/subscriptions.md#activatesubscription) | The payment failed and the activation was reverted: the message ends with the state the subscription is back in (the spec shows `awaiting_signup`). It arrives under `errors.base` | Fix the payment method, then call again on purpose. Never from an automatic retry (R11) |

## 409

| Message | Operation | Cause | Do |
|---|---|---|---|
| `DuplicatePrevention::DuplicateSubmissionError` | [`create_usage`](operations/subscription-components.md#createusage) | A report with this `uniqueness_token` already reached Maxio [docs]. Its outcome is unknown: a 409 never proves success | Follow R11 with `list_usages` for the component and the day, `until_date` set to the next day. Found: done. Still not found once 120 seconds have passed since the first send: R11 step 4 |
| `DuplicatePrevention::DuplicateSubmissionError` | [`signup_with_subscription_group`](operations/subscription-groups.md#signupwithsubscriptiongroup) | A request with this `uniqueness_token` already reached Maxio [docs]. Its outcome is unknown: a 409 never proves success | Follow R11 with `find_subscription` by each subscription's `reference`. Found: settle from what Maxio holds. None found once 120 seconds have passed since the first send: start again with a new token (R11 step 4) |
| `DuplicatePrevention::DuplicateSubmissionError` | [`create_subscription`](operations/subscriptions.md#createsubscription) | A request with this `uniqueness_token` already reached Maxio [docs]. Its outcome is unknown: a 409 never proves success | Follow R11 with `find_subscription` by your reference. Found: settle from what Maxio holds. Still not found once 120 seconds have passed since the first send: start again with a new token (R11 step 4) |
